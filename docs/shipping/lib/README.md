# mushaf.js

A zero-dependency browser library for the Quran page SVGs described in
[`../FORMAT.md`](../FORMAT.md). It does everything `docs/demo` teaches by hand:
metadata without a database, search, highlighting, gap-aware hit testing, mark
styling, theming, cropping, leading, masking, and drag-select-and-copy of real
Quranic text.

**No npm install. No build step. No framework. It never bundles or writes the SVGs.**

> **Working name.** `mushaf.js` / `MushafPage` / the global `Mushaf` are
> placeholders. The name lives in two places — `NAME` in `build-global.js` and the
> class name in `core.mjs` — so renaming is a two-line change.
> Licence: **[to be decided by Abdullah — no terms are stated anywhere in this
> directory].**

## Quick start

```html
<div id="stage"><!-- the page goes here --></div>
<script type="module">
  import { MushafPage, attachSelection } from './lib/mushaf.mjs';
  const page = await MushafPage.load(42, { baseUrl: 'pages/' });  // 1. fetch
  document.getElementById('stage').append(page.el);               // 2. show
  page.highlightAyah('2:255');                                    // 3. highlight
  console.log(page.search('الله').map(m => m.wid));               // 4. search
  attachSelection(page, { citation: true });                      // 5. drag + Ctrl+C
</script>
```

Without modules, use the `<script>` build — same API on one global:

```html
<script src="lib/mushaf.global.js"></script>
<script>
  Mushaf.MushafPage.load(42, { baseUrl: 'pages/' }).then(page => { /* … */ });
</script>
```

| `layout.mjs` | line gap, and the leading that fills a phone screen |
| `overlay.mjs` | the shared per-word hit layer, and hover / click |

| `memorize.mjs` | masking and progressive reveal |
| `a11y.mjs` | accessible text for screen readers |
| `view.mjs` | scroll a word or ayah into view |
| `raster.mjs` | crop → PNG |
| `atlas.mjs` | cross-page lookup (needs a generated index) |
| `markers.mjs` | swappable, recolourable ayah end-markers. **Fetches outlines at runtime; ships none.** |
| `mushaf.mjs` | the barrel: everything |
| `mushaf.global.js` | the `<script>`-tag build, generated by `node build-global.js` |
| **[`API.md`](API.md)** | **the complete API reference — every function, every parameter** |
| [`DESIGN.md`](DESIGN.md) | why the API is shaped this way, and what was dropped |

Import `core.mjs` alone if you only want the page; the extras are free functions
taking a page (`attachSelection(page, …)`, `mask(page, …)`) precisely so a bundler
can drop what you do not use.

## The layer model — read this before combining features

Consumers run several capabilities at once: hover for a gloss, drag to copy, a band
behind the current ayah, per-word highlighting driven by audio timings. They compose
because **the library owns one overlay and solves this once**.

```
   band / highlight layer      first child of <svg>       pointer-events: none
   the SVG ink                 the page itself            pointer-events: none  (while a layer is up)
   the per-word hit layer      a <div> over the <svg>     THE ONLY TAKER
```

One `<span>` per word, on that word's box, carrying its `data-wid`. That is
simultaneously what native selection, hover and gap-aware tapping need, so it is
measured **once** and shared. It is **reference counted**: `attachSelection` and
`onWordHover` turn on and off independently, and detaching one never pulls the layer
out from under the other. It rebuilds on resize — once, for every consumer — and a
live selection survives the rebuild.

Two details that are load-bearing:

- **Every word carries two boxes.** The **ink box** (its own rect) is what a
  highlight band is drawn from, so bands never overhang the text. The **hit box** is
  the ink box grown sideways to meet its neighbours and vertically to the full line
  band, so the layer has **no dead zones** — every point on a printed line belongs to
  exactly one word, and a tap between two words still lands on one.
- **Selection is whole-word, always.** Native `::selection` is suppressed, so a
  partial-word range cannot even be painted.
- **A highlight is ONE path, not a stack of lines.** Every band — ayah, words,
  selection — is a single `<path>` with one subpath per printed line, all wound the
  same way and unioned by an explicit `fill-rule="nonzero"`, with neighbouring
  subpaths overlapping slightly. That kills the antialiasing hairline that otherwise
  makes a six-line ayah read as six stripes. Vertical extent is the line **pitch**,
  not a line's bounding box, which includes ascenders overrunning its neighbour.

If you want none of this, ignore `overlay.mjs`: `page.hitTest()` is pure geometry and
touches no DOM, and `page.onTap()` works with or without a layer.

## Generating the cross-page index

`atlas.mjs` needs a small file the SVGs cannot provide (a page cannot know which page
2:255 is on):

```bash
python3 build-atlas.py /path/to/pages -o atlas.json     # 604 pages, 34 KB raw / 9 KB gzip
```

**Whether that file ships alongside the SVGs is Abdullah's decision.** Everything else
works without it.

## Tested

287 assertions in a real browser (Chromium via Playwright) against real pages —
1, 42, 48, 176, 582, 604 — plus a genuine mouse drag, Ctrl+C, hover, a click in a
6.96 px gap, and a window resize. Zero console errors. See the final section of
[`API.md`](API.md#testing) for what is and is not covered.
